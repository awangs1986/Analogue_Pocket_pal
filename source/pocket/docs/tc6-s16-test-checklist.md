| 1.6 | `pal.pak` 只含你的数据，用 `--verify` 校验通过；OGG 文件名正确（`ogg/01.ogg`、`ogg/02.ogg`…）；记录 SHA-256。 | ☐ | ☐ | | [A] |
| 1.7 | 安全弹出 SD 卡后再拔卡。 | ☐ | ☐ | | [T] |

**制作 pal.pak**（在电脑上，仓库 `work/mister-pal-pocket`（bootstrap 生成的源码树））：

```sh
# pal-data 目录里放一个版本的原版文件：abc.mkf ball.mkf data.mkf f.mkf fbp.mkf fire.mkf gop.mkf
# map.mkf mgo.mkf pat.mkf rgm.mkf rng.mkf sss.mkf m.msg word.dat，以及 voc.mkf 或 sounds.mkf；
# 音乐放在 pal-data/ogg/01.ogg、02.ogg …（必须是真的 Ogg/Vorbis）；可选 sdlpal.cfg 放根目录。
# 文件名只能是 ASCII；目录里不要放无关文件和 .rpg/.sav 存档。
python3 pocket/tools/pack_assets.py /path/to/pal-data /path/to/pal.pak
python3 pocket/tools/pack_assets.py --verify /path/to/pal.pak
sha256sum /path/to/pal.pak
```

不需要转换 MKF 格式；`pal.pak` 只是把这些文件按原样打成一个只读归档（PALPAK1 格式）。
`make_probe_assets.py` 只用于生成合成测试程序（probe）的数据，**不是**游戏数据工具，本包也没有附带 probe。

## 12. 已知限制

- **GPU 是空壳**（EXCLUDE_GPU）：栅栏永远立即"完成"，绘图命令不执行。PAL 只用软件渲染，不受影响；但 `HW_FEATURES` 仍报告 GPU 功能位，任何依赖 GPU 绘图的程序在这个核心上都画不出东西。
- **build_id 为 0**：编译时缺 `apf/build_id.mif`，Pocket 上看到的构建日期/ID 不可信，以本文件和 info.txt 为准。
- **hold 余量只有 +0.009 ns**（快速 85°C，scanout → Analogizer 输出路径）；x_count 跨时钟 hold 最差为 +0.076 ns（快速 0°C）。时序签核通过，但余量很薄，所以请特别留意发热后的画面（9.2）。
- 没有经过任何真机测试；OGG 在 RISC-V CPU 上软件解码，性能未经实测。
- 不支持睡眠；存档必须用菜单 Quit 退出后才算写入 SD 卡；不保证断电安全。
- 默认只提供 normal 和 CRT（0x10），不提供 LCD/灰度模式（见第 11 节）。
- 本包不含 probe 测试程序（宿主机没有 FFmpeg/libvorbis，无法生成合成数据），所以 [A]/[H] 里依赖 probe 的边框/棋盘/椭圆测试改用游戏画面目测。

## 13. 不通过时怎么回退

删除 SD 卡上的以下内容即可完全移除本测试版，不影响其他核心：

- `Cores/awangs1986.PALtc6/`
- `Platforms/sdlpaltc6.json`
- `Assets/sdlpaltc6/`（包括你放的 pal.pak）
- 如果不需要测试存档，再删 `Saves/sdlpaltc6/`（先备份）

本包没有修改任何已有文件，不需要恢复其他东西。

## 14. 出问题时请收集

1. 第 0 节的全部记录（尤其是 Pocket 固件版本、pal.pak 的 SHA-256、本包 SHA-256）。
2. 失败的编号、操作步骤、从启动到出错的时间、能否稳定复现、重启后是否还有。
3. 照片或视频：黑屏/花屏/抖动请录视频（最好能看清像素，慢动作更好）；声音问题录音。
4. 当时的温度情况（刚开机还是已经发热）、是否在 Dock 上、显示模式（normal/CRT）。
5. Pocket 上的错误提示原文（拍照）。
6. 存档问题：出问题前后的 `Saves/sdlpaltc6/` 文件（复制一份，不要覆盖备份）。
7. 同样的 pal.pak 和存档在原正式版 `awangs1986.PAL`（如果有）上是否正常，用来区分是 bitstream 问题还是数据问题。
